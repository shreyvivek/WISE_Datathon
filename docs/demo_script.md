# 3-minute demo (all numbers measured; see docs/model_evaluation.md)
Hard limit: 3:00 (compulsory). The guide asks the video to cover: **problem, data supporting the problem, solution, and how it leverages IBM Z - show the tech stack, the LinuxONE instance and the model.**
**0:00-0:25 Problem.** "Two applicants. Similar financial profiles. Different decisions. Who checks why?" Banks use complex processes, but public HMDA data lets us examine decision patterns independently.
**0:25-0:50 Solution / Overview page.** SecondLook: 37,491 comparable Maryland mortgage applications (HMDA 2025), 2,600 denials, 447 lenders. For each denial it finds approved applications from the *same lender* with closely similar finances. 1,338 denials have a strong comparator; 1,726 are queued; 874 say "Insufficient comparable evidence" - we don't force cases.
**0:50-1:35 Financial Twins page.** Pick case `b81daae6eb`: left, the denied application; right, three approved twins. Point at matching fields, the match-quality label, any missing fields, the stated denial reason (context only, never used for matching). Click *Generate reviewer note*: Granite note (cached), "validated", plus the fixed caveat: public data omits credit scores, so a difference in outcome does not establish an error.
**1:35-2:10 Blind Review -> Fairness.** Blind Review ON: matching used only financial fields. Toggle *Reveal demographic patterns* (token-gated). Black vs White denial gap: raw 8.4 pp, after financial matching 3.1 pp (95% CI 2.0-4.1). Asian vs White: 1.1 pp, interval touches zero. Say: "These are observed disparities that depend on matching strictness (1.7-4.9 pp across settings) - they raise questions, they are not proof." Optional 10 s: Model Sensitivity page (XGBoost on LinuxONE), and SHED/Census context.
**2:10-2:45 IBM LinuxONE (show the instance, the tech stack and the model).** Tech stack slide/flowchart (docs/architecture.md): HMDA/SHED/ACS -> pandas/NumPy matching + scikit-learn/XGBoost -> FastAPI (3 workers, systemd) -> Granite 4.0 via llama.cpp in the provided container -> Streamlit. Platform capabilities to point at: container (Granite), security (token-gated demographic endpoints, no PII in logs, SSH-only exposure), compute (3 vCPU, ~118 MB/worker, ~440 req/s under 4-8 clients). Terminal: Terminal: `uname -m` = s390x; `systemctl is-active`; live `/analyse-application` (labelled SIMULATION): ~3-5 ms server-side; full matching of 37,491 applications on the VM in under a second (same-lender), identical results to a laptop; Granite 4.0 running in the provided container with llama.cpp. Honest line: "the VM isn't faster than a laptop here - the point is that the whole audit pipeline, including generative notes, runs on LinuxONE and reproduces bit-for-bit."
**2:45-3:00 Impact.** "SecondLook doesn't decide who deserves a mortgage. It helps ensure that decisions worth questioning don't disappear into millions of records."
