System architecture. Public data goes through a cohort filter that splits it into three tables: finances only for matching, demographics kept separate, and denial reasons for display only. Matching, the blind fairness audit, the XGBoost sensitivity model and the API run on the IBM LinuxONE VM, with Granite served from the IBM-provided container. The API is reached over an SSH tunnel by the reviewer dashboard, and a human reviewer makes advisory decisions that are written to an audit trail.
